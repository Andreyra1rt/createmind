# CreateMind Project Workspace Architecture (v2)

В данном документе описывается концептуальная архитектура и структура рабочего пространства проекта (**Project Workspace v2**).

---

## 1. Workspace Purpose

* **Зачем существует Project Workspace?**
  Рабочее пространство проекта — это среда реализации. В то время как AI Discovery служит для понимания задачи, Workspace предназначен для её воплощения. Это цифровой офис, в котором абстрактная бизнес-идея пользователя превращается в осязаемое техническое решение под его полным контролем.
* **Что является его основной задачей?**
  Предоставить пользователю прозрачный, интерактивный интерфейс для управления всеми аспектами реализации его проекта: бэклогом задач, архитектурными схемами, генерируемыми файлами, ИИ-сотрудниками и историей изменений.
* **Почему пользователь возвращается именно сюда?**
  Чтобы проверить текущий статус выполнения задач, дать обратную связь ИИ-команде, скачать обновленные файлы (код, спецификации) и управлять жизненным циклом проекта.

---

## 2. Workspace Entry

* **Что пользователь видит сразу после создания проекта?**
  Сразу после завершения опросника AI Discovery (состояние `SAVED`) пользователь перенаправляется в Workspace и видит карточку **Overview** (Обзор проекта). Она содержит краткое описание сути проекта, определенный ИИ тип системы, статус готовности и текущий фокус работы ИИ-команды.
* **Что является первым экраном Workspace?**
  Первым экраном (активной вкладкой) всегда является **Overview**, чтобы предоставить пользователю быстрый контекст без перегрузки деталями.

## 3. Workspace Zones

### Overview (Обзор)
* **Назначение**: Быстрая сводка о проекте, его целях и текущем прогрессе.
* **Когда появляется**: Сразу при создании Workspace.
* **Какие данные хранит**: Описание проекта, статус-бейдж, прогресс-бар выполнения задач.
* **С чем взаимодействует**: Отображает агрегированную информацию из разделов Tasks и Architecture.

### Architecture (Архитектура)
* **Назначение**: Визуализация структуры создаваемого решения, выбранного технологического стека и модулей.
* **Когда появляется**: Сразу при создании Workspace.
* **Какие данные хранит**: Оценку сложности, концептуальное описание, дерево модулей/компонентов.
* **С чем взаимодействует**: Передает список необходимых модулей в Tasks для формирования бэклога.

### Tasks (Задачи)
* **Назначение**: Интерактивный двухэтапный чек-лист (вехи разработки и конкретные подзадачи).
* **Когда появляется**: Сразу при создании Workspace.
* **Какие данные хранит**: Задачи, их статусы (ожидает, в процессе, выполнено), отметки пользователя о выполнении.
* **С чем взаимодействует**: Отправляет сигнал во вкладку Activity при изменении статуса задачи.

### Files (Файлы)
* **Назначение**: Каталог всех сгенерированных ИИ-командой проектных документов и кода.
* **Когда появляется**: По мере генерации первого файла.
* **Какие данные хранит**: Имена файлов, их форматы (PDF, JSON, JS), размер, ссылки на скачивание.
* **С чем взаимодействует**: Читает данные из вкладки Architecture для привязки файлов к конкретным модулям.

### AI Team (ИИ-команда)
* **Назначение**: Управление ИИ-агентами, закрепленными за проектом.
* **Когда появляется**: Сразу при создании Workspace.
* **Какие данные хранит**: Список агентов (Tech Lead, PM, Analyst), их роли, зоны ответственности и текущие статусы активности (Idle / Processing).
* **С чем взаимодействует**: Реагирует на клики по задачам из вкладки Tasks, имитируя работу соответствующего агента.

### Knowledge (Знания)
* **Назначение**: Единый справочник требований и бизнес-правил проекта.
* **Когда появляется**: Сразу при создании Workspace.
* **Какие данные хранит**: Контекст, собранный на этапе Discovery, ограничения проекта, предпочтения пользователя.
* **С чем взаимодействует**: Служит базовым контекстом для работы ИИ-агентов.

### Activity (Лог действий)
* **Назначение**: Хронологическая лента событий по проекту.
* **Когда появляется**: По мере выполнения первых действий ИИ или пользователем.
* **Какие данные хранит**: Временные метки, текст события (например, *"Tech Lead сгенерировал файл schema.json"*), автора события.
* **С чем взаимодействует**: Записывает активность из AI Team и Tasks.

## 4. Navigation

* **Постоянные разделы**:
  * `Overview` (всегда доступен для оценки статуса).
  * `Architecture` (остается неизменным ориентиром проекта).
  * `Tasks` (основная рабочая область пользователя).
  * `AI Team` (список исполнителей).
* **Динамические разделы (появляются по мере развития проекта)**:
  * `Files` (скрыт, пока ИИ-команда не сгенерирует первый файл/схему).
  * `Activity` (скрыт на самом старте, пока лог пуст).
* **Скрываемые разделы**:
  * `Knowledge` (может сворачиваться в боковую панель для экономии экранного пространства).

## 5. User Journey

```text
Пользователь открывает проект
        │
        ▼
Читает Overview (Оценивает общий статус)
        │
        ▼
Переходит к Architecture (Изучает предложенные модули и стек)
        │
        ▼
Утверждает архитектуру (Дает добро на генерацию)
        │
        ▼
Получает Tasks (Видит сгенерированный чек-лист)
        │
        ▼
Работает с AI Team (Запускает выполнение задач агентами)
        │
        ▼
Загружает Files (Забирает готовый код и спецификации)
        │
        ▼
Возвращается позже (Для контроля новых этапов)
```

## 6. Workspace Principles

1. **Один Workspace = один проект**. Полная изоляция контекстов и файлов для предотвращения утечек данных между проектами.
2. **Workspace хранит весь контекст проекта**. Вся история, знания и файлы никогда не удаляются и доступны в любой момент.
3. **AI работает внутри Workspace**. ИИ-агенты привязаны к рабочей области и оперируют только ее данными.
4. **Пользователь никогда не теряет историю проекта**. Любое действие логируется в Activity.
5. **Все действия происходят внутри Workspace**. Пользователю не нужно переходить на сторонние сервисы для скачивания файлов или контроля бэклога.
6. **Постепенное раскрытие сложности**. Разделы интерфейса появляются динамически (например, вкладка Files), не перегружая пользователя на старте.

## 7. Future Expansion

* **Совместная работа (Multi-user)**: Возможность приглашать команду (дизайнеров, разработчиков) в Workspace с разграничением прав доступа.
* **Комментирование**: Оставление комментариев и правок непосредственно на схемах во вкладке Architecture.
* **Версионирование**: Сохранение промежуточных версий архитектуры и бэклога с возможностью отката.
* **AI Marketplace**: Подключение специализированных внешних ИИ-агентов (например, QA-агента или SEO-оптимизатора) под конкретные задачи проекта.
* **Внешние интеграции**: Автоматическая синхронизация бэклога с Jira/Trello и деплой кода напрямую в репозитории GitHub/GitLab.
